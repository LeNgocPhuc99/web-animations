11 Best Practices & Common Pitfalls

Những lỗi hay gặp nhất khi dùng GSAP và cách tránh chúng. Performance tips, cleanup patterns, và mental models đúng để viết animation maintainable.

dos & don'ts
performance
debug toolkit
mental model
✅ Dùng gsap.set() để init
Set trạng thái ban đầu bằng gsap.set() thay vì CSS — đảm bảo GSAP biết điểm xuất phát và không có flash khi animate.
❌ Mix CSS transition + GSAP
Đừng để cùng property có cả CSS transition và GSAP tween — chúng conflict nhau. Chọn một trong hai, thường là GSAP.
✅ Lưu tween vào biến
Luôn const tween = gsap.to(...) để có thể pause(), kill(), reverse() sau này. Tránh anonymous tween không quản lý được.
❌ Tạo tween trong render loop
Đừng tạo tween trong onUpdate callback hay RAF loop — mỗi frame tạo một tween mới làm memory leak. Tạo một lần, control nhiều lần.
✅ clearProps sau animation
clearProps: 'all' xoá inline styles sau khi xong — trả element về CSS class ban đầu. Quan trọng khi element cần responsive layout sau animation.
❌ Animate layout properties
Tránh animate width, height, top, left, margin. Dùng x/y, scaleX/Y, xPercent thay thế.
// ✅ pattern chuẩn cho animated component
gsap.set(el, { opacity:0, y:20 });              // 1. init state
const tween = gsap.to(el, { opacity:1, y:0, duration:0.6,
  clearProps: 'all' });                          // 2. animate + cleanup
return () => tween.kill();                        // 3. cleanup
⚡ will-change trước animation
Set will-change: transform trên element sắp animate để browser tạo GPU layer trước. Remove sau khi animation kết thúc tránh layer bloat.
⚡ gsap.killTweensOf()
Gọi gsap.killTweensOf(el) trước khi tạo tween mới trên cùng element — tránh stacking tweens không cần thiết, đặc biệt trong event handlers.
⚡ Dùng ticker của GSAP
Thay requestAnimationFrame tự viết, dùng gsap.ticker.add(callback) — GSAP tối ưu ticker để sync với render cycle, tránh double rAF.
⚡ lazyRender: true (mặc định)
GSAP dùng lazy rendering — gộp DOM write cuối mỗi tick để tránh layout thrashing. Đừng override gsap.config({force3D: 'auto'}) trừ khi có lý do.
⚡ Batch ScrollTriggers
ScrollTrigger.batch() xử lý nhiều elements trong một trigger thay vì tạo riêng từng cái — giảm số lượng IntersectionObserver đáng kể.
⚡ prefers-reduced-motion
Luôn wrap GSAP animations trong matchMedia('(prefers-reduced-motion: no-preference)') — GSAP 3.x có gsap.matchMedia() để xử lý sạch.
// gsap.matchMedia() — handle reduced motion + breakpoints
const mm = gsap.matchMedia();
mm.add('(prefers-reduced-motion: no-preference)', () => {
  gsap.from('.hero', { y:60, opacity:0 });
  return () => {}  // cleanup tự động khi media query thay đổi
});

lỗi hay gặp nhất
• Element không tìm thấy → selector sai hoặc DOM chưa render
• Animation flash → thiếu gsap.set() init trước khi from()
• Tween không chạy → element có display:none hoặc visibility:hidden
• Conflict với CSS → có CSS transition trên cùng property
• Memory leak → không cleanup trong React useEffect
• ScrollTrigger sai vị trí → chạy trước khi font/image load xong

// xem tất cả tweens đang active
gsap.globalTimeline.getChildren(true, true, true).forEach(t => console.log(t));
// force refresh ScrollTrigger sau dynamic content load
ScrollTrigger.refresh();
GSAP là transport layer, không phải design tool
GSAP không giúp bạn quyết định animation trông như thế nào — đó là công việc của bạn. GSAP chỉ đảm bảo nó chạy đúng, đủ mượt, và đúng lúc. Thiết kế animation trước trên giấy hoặc Figma, rồi mới code.
Tween = mô tả trạng thái, không phải lệnh
gsap.to(el, {x:100}) không nói "di chuyển 100px từ đây". Nó nói "element này phải ở x=100". GSAP tự tính toán từ trạng thái hiện tại đến đó. Đây là lý do fromTo() đáng tin cậy hơn from() trong timeline phức tạp.
Timeline = choreographer, Tween = dancer
Timeline không animate gì cả — nó chỉ điều phối thứ tự và timing của các Tween. Hiểu cái này giúp debug: nếu animation sai, vấn đề thường là ở position parameter trong timeline, không phải tween.
